# 虚拟化 

## vsphere是VMware虚拟化套件，VC和ESXI是内部组件

## 标准交换机和分布式交换机区别

## 1. 标准交换机（vSphere Standard Switch, VSS）

-   **作用范围**：仅限单个 ESXi 主机。
-   **配置方式**：每台主机单独配置，需要在每台 ESXi 上重复操作。
-   **管理方式**：本地主机级管理，通过 vSphere Client 操作。
-   **功能特点**：
    -   支持基本的 VLAN、端口组、链路聚合（NIC Teaming）。
    -   不支持集中管理的高级功能，如跨主机的网络策略统一。
    -   适合小型环境或者实验环境。

------

## 2. 分布式交换机（vSphere Distributed Switch, DVS）

-   **作用范围**：跨多台 ESXi 主机统一管理。
-   **配置方式**：集中配置一次即可应用到所有加入 DVS 的主机。
-   **管理方式**：通过 vCenter 集中管理。
-   **功能特点**：
    -   支持高级网络功能，如：
        -   分布式端口镜像（Port Mirroring）
        -   NetFlow 流量监控
        -   DHCP/VMkernel 流量管理
        -   私有 VLAN（PVLAN）
    -   网络策略在整个 DVS 上一致，简化大规模环境管理。
    -   支持 vMotion、HA 等高级功能更方便，因为网络配置统一。

------

## 3. 对比表格

| 特性           | 标准交换机 (VSS)       | 分布式交换机 (DVS)                |
| -------------- | ---------------------- | --------------------------------- |
| 管理范围       | 单台 ESXi 主机         | 多台 ESXi 主机集中管理            |
| 配置方式       | 每台主机单独配置       | 集中配置一次，多主机共享          |
| 管理工具       | vSphere Client         | vCenter                           |
| 高级功能支持   | 基本 VLAN、NIC Teaming | PVLAN、NetFlow、Port Mirroring 等 |
| 网络策略一致性 | 不保证                 | 全局统一                          |
| 适用场景       | 小型环境、测试环境     | 大型生产环境、跨主机网络          |

------

💡 **总结**：

-   **VSS**：灵活、简单，但配置分散；适合小环境。

-   **DVS**：集中管理、功能强大，适合大规模或生产环境。

## vSAN和HA

## 1. vSAN（Virtual SAN）

**全称**：VMware vSphere Virtual SAN

**作用**：分布式存储虚拟化

-   将多台 ESXi 主机的本地存储（硬盘/SSD）聚合成一个共享的分布式存储池。
-   虚拟机可以直接在这个存储池上创建和运行磁盘，无需传统的 SAN/NAS。

**核心功能**：

-   数据冗余：支持 RAID-1（镜像）、RAID-5/6（校验）等策略，保证存储可靠性。
-   存储策略驱动管理（SPBM）：可以为每台 VM 定制不同的存储策略（性能、冗余、容量）。
-   高性能：支持全闪存（All-Flash）、混合（SSD+HDD）等模式。
-   集群感知：vSAN 集群内的 VM 数据自动分布和复制，保证容错。

**依赖条件**：

-   需要至少 3 台 ESXi 主机（对于冗余和故障容忍）。
-   需要 vSAN 许可。

**应用场景**：

-   构建全虚拟化存储，无需传统 SAN/NAS。
-   高性能数据库、VDI 桌面虚拟化。
-   灾备环境（通过 vSAN Stretched Cluster 实现跨机房容错）。

------

## 2. HA（High Availability，高可用性）

**全称**：vSphere High Availability

**作用**：虚拟机级别的高可用性

-   当 ESXi 主机出现故障时，自动在集群内其他健康主机上重启受影响的虚拟机。
-   保证虚拟机尽可能短时间停机恢复。

**核心功能**：

-   自动检测主机故障（通过心跳检测）。
-   自动在健康主机上重启 VM。
-   配合 vMotion，可动态维护集群。

**依赖条件**：

-   至少 2 台 ESXi 主机组成 HA 集群。
-   可选与 vSAN 配合，实现存储高可用（即 VM 存储在 vSAN 上）。

**应用场景**：

-   虚拟机关键服务的容错。
-   主机硬件或 ESXi 系统故障恢复。

------

## 3. 对比总结

| 特性     | vSAN                     | HA                    |
| -------- | ------------------------ | --------------------- |
| 功能定位 | 分布式存储虚拟化         | 虚拟机高可用性        |
| 主要作用 | 提供共享、高性能存储     | 主机故障时自动重启 VM |
| 依赖条件 | ESXi 主机 + vSAN许可     | ESXi 主机 + HA许可    |
| 故障处理 | 数据块冗余，存储容错     | VM 在其他主机上重启   |
| 应用场景 | 数据存储优化、分布式存储 | VM 连续可用性、容错   |

------

💡 **总结一句话**：

>   vSAN 是**存储级别的分布式可靠性**，HA 是**计算/虚拟机级别的高可用性**。二者可以配合使用：VM 存在 vSAN 上，同时启用 HA，保证既不丢数据，又能快速恢复 VM。

##  三、关键总结（考试/面试重点）

👉 最标准答案：（三副本）

>   **vSAN 最低需要 3 台 ESXi 主机，或者 2 台主机 + 1 个 见证 节点。**

👉 补充一句更专业：

>   每台主机至少需要一个缓存设备和一个容量设备，并配置 vSAN 网络。

### **vMotion 简述**

**vMotion** 是 VMware 提供的一项核心功能，用于 **在不停机的情况下，将运行中的虚拟机从一台物理主机迁移到另一台物理主机**。

#### **主要特点：**

1.  **无中断迁移**
     用户和应用几乎感觉不到停机，迁移过程中虚拟机继续正常运行。
2.  **在线迁移 CPU 和内存状态**
     vMotion 会复制虚拟机的内存内容、CPU状态和网络连接信息到目标主机。
3.  **保留 IP 和 MAC 地址**
     虚拟机迁移后保持原有网络配置，无需修改。
4.  **依赖共享存储**
     传统 vMotion 需要源主机和目标主机访问相同的存储（如 SAN、NAS 或 vSAN）。

#### **工作流程简化版：**

1.  **初始化迁移**：vCenter 指令开始迁移过程。
2.  **复制内存页**：源主机的虚拟机内存逐页复制到目标主机。
3.  **跟踪变化**：源主机记录迁移期间被修改的内存页。
4.  **最终同步与切换**：暂停虚拟机几十毫秒，复制剩余的内存页，切换运行到目标主机。
5.  **完成迁移**：虚拟机在新主机上继续运行，用户无感知。

------

💡 **小提示**

-   vMotion 对 CPU 类型、主机版本和网络配置有要求，但可以通过 **EVC（Enhanced vMotion Compatibility）** 来解决 CPU 兼容性问题。
-   如果连存储也迁移，就叫 **Storage vMotion**。
